reference/glossary.md:- **instance-spec** — a living registry of the instance's canonical surfaces ("the system's table of contents"): lines "name → purpose in one line → path from the instance root", sections per repo (the workspace repo / the operational repo / the root adapter); carrier — the surface inventory (an instance-state role, resolved via the instance's `carrier declaration`). Carrier separation: the instance's AGENTS.md canon — rules and processes, instance-spec — the inventory of "what exists" facts; the AGENTS.md topology map — the frozen path schema, instance-spec — a living registry. Updated by deltas of the classes ADDED/MODIFIED/REMOVED by the name-status of the closing cycle's changeset, applied by reconcile-change intra-changeset (a body edit before land; the journal — git history). Distinction from **instance-state**: instance-state — the typed-anchor convention for the consumer's project artifacts (the placement mechanism outside the corpus), instance-spec — the instance's own registry-table of contents. Basis: Bohner–Arnold 1996 (eds.), *Software Change Impact Analysis* (IEEE CS Press — impact analysis: an edit → the derived surfaces of the registry); the living-spec-with-deltas genre precedent — OpenSpec (openspec.dev).
