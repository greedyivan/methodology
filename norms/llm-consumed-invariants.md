# LLM-consumed invariants — authoring checklist: 1–5 — SKILL.md diffs; No. 6 — the class of LLM-consumed surfaces

Authoring invariants: discrete check questions. Invariants 1–5 — SKILL.md diffs (and skill assets); No. 6 — the class of LLM-consumed surfaces (the inventory lives in No. 6). The resync rule is at the end; attributions in a single section below.

1. **Two loads.** Every unit of content carries a contextual load (tokens/attention — paid every turn) or addresses a cognitive one (a human keeps the index "what exists and when to take it"). Check: a unit carrying neither is crossed out. Counterexample: duplicating a subagent mandate in SKILL.md — pays the contextual one every turn, adding nothing.
2. **Progressive disclosure by branch.** Inline — what every branch of execution needs; behind a pointer (file/section) — what only some need. Check: material needed by a single role/branch sitting inline in the shared text → move it behind a pointer. Counterexample: the full interview protocol in SKILL.md while a subagent executes it by charter.
3. **Completion criterion = clarity + demand.** Every step is phrased with a verifiable done/not-done boundary (clarity) and a requirement that generates work (demand: "every changed model accounted for", not "compile a list"). Check: a step that cannot be judged "done/not-done" must be restated; a step that generates no action → delete. Counterexample: "ensure completeness" — not verifiable, generates no work.
4. **Positive formulations.** Rules are written as "what to do", not "what not to do" (negation in pre-training activates the negated target — "don't think of an elephant"). Check: "don't X" → restate as "Y". Counterexample: "do not decide silently" → "present the verdict + options to the author".
5. **No-op line test.** Deleting the line changes no agent behavior → the line is a no-op and is deleted; a dispute over no-op status is settled by a run (whether behavior changes is empirics, not debate). Check: every line of text survives this test. Counterexample: retelling a glossary term in SKILL.md — the behavior is already defined by the glossary reference.
6. **Eval-first.** A behavioral change — baseline run: a representative task before and after the edit, observation via telemetry/trace; the difference of outcomes and the telemetry pointer — in the changeset's commit message. A new skill — first a trial run of the target task without the skill; SKILL.md is authored against the gaps of that run. Check: an edit that changes the set/semantics of instructions (task triggers, steps, gates, output formats, stopping conditions) — the changeset carries run evidence; a typographical one (no instruction change) is free to land; a dispute is settled by a run. Counterexample: a skill nobody has run.
   - Scope of No. 6 — the class of LLM-consumed surfaces (surfaces whose instructions are consumed by LLM sessions). The inventory domain of No. 6 is the methodology repository (this repo); workspace-repo surfaces are LLM-consumed by the content definition (glossary `LLM-consumed`) but outside this gate until a separate authoring decision. The class IS this inventory; extension — only via re-decomposition by the collapse mechanics, never by in-place edits. The inventory is a static snapshot of the run `git ls-files '*.md'` at the current tree (re-derived and re-pinned by the program that changes the class; the deltas of the `publication` program: W1 −14 removed-skill paths, W2 +1 docs/casebook.md — raw 34 → 21, class counter 33 → 20); the initial commit of the public history is the first public pin.    - Out of class: data registries (surface inventories, the deferred-options registry), docs prose (in this repo: docs/methodology.md), markup templates — read as data/descriptions; a borderline file is classified by a content run (is the file read by a session as an instruction?).
   - A behavioral change to a non-skill surface — the categorical criterion: instructive text = routing, task intake, gates, output formats, stopping conditions, glossary term rules; an edit to these categories in any file of the class → the changeset carries run evidence; prose (attributions, preambles, justifications) is free to change; a dispute is settled by a run.
   - Bootstrap: a changeset changing this very norm carries baseline-run evidence — a fresh-context verdict on whether the changeset must carry run evidence or is exempt, taken on the diff of a non-skill surface before and after the norm edit; the difference of outcomes — in the run artifact, the pointer — in the commit message.
   - Eval-first evidence form (validated core, a real spike series): one fresh-context run per changeset; run tasks pin categorical criteria; hard answer template = decision + verbatim quote-anchor; binary grid (a difference = decision OR anchor-string divergence); scoring against a pre-recorded RU-baseline; the run form + the scoring are artifacts of the changeset, the pointer lives in the commit message.
   - Blind spots of the single run — each behavioral changeset closes every zone with an explicit check line in the run form, check type per zone (run-pins derive from the validated baseline runs of the originating program):
      1. categorical-criterion removal — check: line-alignment diff RU↔EN (parity of blocks/lines of the fragment + parity of categorical entity lists); run-pin: a wc/diff line-parity pair over the faithful and corrupted variants (validated baseline runs).
      2. output-format drift outside binary checks — check: template-field scan of the run form (every hard-template field present; FORMAT-FAIL channel); run-pin: format-fails = 0 in the validated baseline scoring.
      3. injections in uncovered zones — check: mechanical inventory reconciliation — lines not pinned by run tasks are grep/diff-checked against the original; run-pin: the No. 6 inventory snapshot + a per-path existence check.
      4. gradual weakenings — check: modality parity — count of deontic must-markers of the RU fragment = count of the EN version; run-pin: modality-marker counts over the faithful/corrupted variants (validated baseline runs).
      5. paraphrase evasion — check: quote verbatimness — every quote-anchor of the run form verified by grep -F against the fragment; run-pin: quote verbatimness by grep -F, MISS = 0 (validated baseline scoring).

## Resync rule (k14)

A change of skill behavior ⇒ a same-changeset delta: the skill's row in README + glossary (if terms are affected). Antipattern — "a router that lies" (README describes behavior that no longer exists).

## Attributions

- **Invariants 1–5** — writing-for-agents patterns, grounded: Sweller, cognitive load theory (progressive disclosure = load management); ASD-STE100 (controlled language, positive formulations); the no-op test — a behavioral criterion (settled by a run, not interpretation).
- **Resync rule** — Bohner–Arnold 1996, *Software Change Impact Analysis* (ripple: a change must propagate to dependent artifacts); ISO/IEC/IEEE 26531:2023 (content management, single-sourcing consistency); Li et al. 2022, *Cybersecurity* 5:1 (empirics: documentation desync → growing maintenance cost).
- **Invariant 6 (eval-first)** — Anthropic engineering, "Equipping agents for the real world with Agent Skills" (Barry Zhang, Keith Lazuka, Mahesh Murag, published 2025-10-16), guideline "Start with evaluation"; https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills — accessed 2026-09-11.
- **Scope extension of No. 6 (the class of LLM-consumed surfaces)** — the decision registry of the disposition program (a reconcile round item); class composition verified by the inventory run git ls-files '*.md' at the program's base commit (pre-publication history).
